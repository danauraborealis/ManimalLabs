Distribution solved, fully Forge-compliant (verified 2026-08-15) — NO StreamingAssets files needed, unlike Icebreaker:
- `Class3526.method_0` (AssetsManagerClass.cs:656) decouples bundle fetch from scene load: it calls `BundlesManager.LoadBundleAsync(bundleName, logErrors:false)` — which for built-in scene paths 404s SILENTLY (UnityWebRequest against DownloadingUrl, error just stored, never thrown; BundlesManagerClass.Class3524) — then loads by `SceneManager.LoadSceneAsync(sceneNameWithoutExtension)`. SceneManager finds scenes in ANY AssetBundle in memory regardless of who loaded it.
- So: plugin ships `manimal_labs_boiler.bundle` NEXT TO THE DLL, calls `AssetBundle.LoadFromFile(pluginDir/...)` itself, and Harmony-prefixes `GClass2287.method_1(ScenesPreset)` (the INSTANCE method — NOT smethod_1: the main path goes method_0 → this.method_1 directly, smethod_1 only handles child presets; method_1 catches both) to swap the floor_1 entry in `_scenesResourceKeys` when `ServerName == "laboratory"`. Native loader awaits/activates our scene like any other.
- The bundled scene must get a DISTINCT name in the SDK (e.g. `Laboratory_Office_Above_Boiler_Room_floor_1_MX`) — LoadSceneAsync by name is ambiguous if a bundle scene shares a build-settings scene's name. Make the swap idempotent (method_1 can run more than once) and unload the bundle on raid end.
